### Phase 1: The "Ghost in the Machine" (Anti-Cheat & Anti-Piracy)
For a single-player/co-op JRPG, the best anti-piracy isn't a crash screen (pirates use crashes to test if their crack worked). The best method is **Silent Corruption** and **Memory Obfuscation**.

#### 1. Memory Obfuscation (Anti-Cheat Engine)
Tools like Cheat Engine scan your PC's RAM for exact numbers (e.g., scanning for "100" to find your HP). We will create a custom data type that scrambles the number in memory using a random key.

**How to add this:** Create a new script named `SecureInt.gd` and paste this code.
```gdscript
# SecureInt.gd
class_name SecureInt
extends RefCounted

var _encrypted_value: int
var _key: int

func _init(initial_value: int = 0) -> void:
    _key = randi() # Generate a random 32-bit integer key
    set_value(initial_value)

func set_value(value: int) -> void:
    # XOR the value with the key to hide it in memory
    _encrypted_value = value ^ _key 

func get_value() -> int:
    # XOR it again to reveal the real number to the game engine
    return _encrypted_value ^ _key

# Optional: Periodically change the key to defeat advanced memory scanners
func rotate_key() -> void:
    var real_value = get_value()
    _key = randi()
    set_value(real_value)
```
*Usage:* Instead of `var hp: int = 100`, you will use `var hp: SecureInt = SecureInt.new(100)`. To get the HP, you call `hp.get_value()`. Cheat Engine will be completely blind.

# This dictionary holds ALL the hidden data across the entire trilogy
var profile_data: Dictionary = {

    "trilogy_choices": {}         # e.g., {"spared_the_villain": true}

# We save to the Documents folder so Game 1, 2, and 3 share this exact file!
var save_path = OS.get_system_dir(OS.SYSTEM_DIR_DOCUMENTS) + "/ChronoTrilogy/global_profile.json"

func _ready():
    load_profile()

# Call this to set a hidden flag during the story
func set_flag(flag_name: String, value) -> void:

    save_profile()

# Call this to check if a flag exists
func get_flag(flag_name: String, default_value = false):
    if profile_data["secret_flags"].has(flag_name):
        return profile_data["secret_flags"][flag_name]
    return default_value

# Automatically saves the JSON file to the hard drive
func save_profile() -> void:
    # Ensure the folder exists
    DirAccess.make_dir_recursive_absolute(save_path.get_base_dir())
    var file = FileAccess.open(save_path, FileAccess.WRITE)
    if file:
        file.store_string(JSON.stringify(profile_data))
        file.close()

# Reads the file when the game boots up
func load_profile() -> void:

        var json_string = file.get_as_text()
        file.close()
        var json = JSON.new()

### Step 1: The Mod Manager Autoload
This script will scan a `mods/` folder on startup, read JSON files, validate them, and merge them into a central registry. It prioritizes mod data over base game data, allowing seamless overrides.

Create `ModManager.gd` and add it to **Autoloads**:
```gdscript
# ModManager.gd (Autoload)
extends Node

# Central registry that holds ALL game data (base + mods)
var registry: Dictionary = {
    "items": {},
    "characters": {},
    "dialogue_timelines": {}
}

const MODS_DIR = "user://mods/"

func _ready():
    _ensure_mods_folder()
    load_all_mods()
    print("Mod Manager Ready. Loaded ", registry["items"].size(), " items, ", registry["characters"].size(), " characters.")

func _ensure_mods_folder():
    if not DirAccess.dir_exists_absolute(MODS_DIR):
        DirAccess.make_dir_recursive_absolute(MODS_DIR)

func load_all_mods():
    var dir = DirAccess.open(MODS_DIR)
    if not dir: return
    
    dir.list_dir_begin()
    var folder = dir.get_next()
    while folder != "":
        if dir.current_is_dir() and not folder.begins_with("."):
            _load_mod_folder(MODS_DIR + folder + "/")
        folder = dir.get_next()
    dir.list_dir_end()

func _load_mod_folder(mod_path: String):
    var manifest_path = mod_path + "manifest.json"
    if not FileAccess.file_exists(manifest_path):
        print("Skipping folder (no manifest): ", mod_path)
        return

    var manifest = _safe_load_json(manifest_path)
    if manifest.is_empty(): return
    
    print("Loading Mod: ", manifest.get("name", "Unknown"))
    
    # Merge data files if they exist
    _merge_json_to_registry(mod_path + "items.json", "items")
    _merge_json_to_registry(mod_path + "characters.json", "characters")
    
    # Register custom Dialogic timelines
    _register_dialogic_timelines(mod_path)

func _merge_json_to_registry(file_path: String, category: String):
    var data = _safe_load_json(file_path)
    if data.is_empty(): return
    
    for key in data:
        # Validate required fields to prevent crashes
        if _validate_entry(category, data[key]):
            registry[category][key] = data[key] # Mods automatically override base data

func _safe_load_json(path: String) -> Dictionary:
    if not FileAccess.file_exists(path): return {}
    var file = FileAccess.open(path, FileAccess.READ)
    var json = JSON.new()
    var err = json.parse(file.get_as_text())
    file.close()
    if err == OK: return json.data
    print("JSON Parse Error in: ", path)
    return {}

func _validate_entry(category: String, entry: Dictionary) -> bool:
    match category:
        "items": return entry.has("name") and entry.has("type")
        "characters": return entry.has("name") and entry.has("max_hp")
    return true

# Safe getter for your existing systems
func get_data(category: String, id: String, fallback = null):
    if registry[category].has(id):
        return registry[category][id]
    return fallback
```

### Game 1: The *Chrono Trigger* System (Spatial Turn-Based)
In *Chrono Trigger*, positioning matters. If enemies clump together, a Dual Tech (like a whirlwind attack) hits all of them. 

**1. The "Slot" System:**
When the *Golden Sun* camera swoops down, you don't need to write code to snap characters into place. 
*   Place **Marker3D** nodes on your grid where you want characters to stand (e.g., `Slot_FrontLeft`, `Slot_BackRight`). 
*   When combat starts, you simply tell the character's 3D model to `look_at` the enemy and move to the nearest Marker3D.

**2. Designing the "Dual Tech" (Zero Math):**
How do we make a massive hammer attack hit three enemies at once without calculating their coordinates?
*   **The Hitbox:** Add an **Area3D** node to your "Cute Bruiser" character. Give it a massive **CollisionShape3D** (a big sphere around her). By default, turn this Area3D *off* in the Inspector (uncheck "Monitoring").
*   **The Animation:** Open her **AnimationPlayer**. Create the `Hammer_Smash` animation. 
*   **The Visual Trigger:** In the animation timeline, at the exact frame where the hammer hits the ground, add a **Call Method Track**. Tell it to turn *on* the Area3D (`set_deferred("monitoring", true)`). At the end of the swing, turn it back off.
*   **The Result:** If any enemy's physical 3D body is inside that sphere when the hammer drops, Godot automatically registers the hit. If enemies clump together, they all get hit!

### Game 2: The *Triangle Strategy* System (Tactical Grid)
Here, the grid is king. Height, facing direction, and elemental terrain dictate the battle. We will use Godot’s visual **NavigationRegion3D** (which we baked earlier) to handle movement.

**1. The "Ghost Tile" Movement:**
When it’s a character's turn, you want to show the player exactly where they can move.
*   Create a simple 3D Cube, make its material translucent/blue, and turn it into a **Scene** (save it as `GhostTile.tscn`).
*   Add a **RayCast3D** to your Camera. It shoots an invisible laser down to the grid wherever your mouse cursor is.
*   When the RayCast hits a valid navigation tile, you visually spawn the `GhostTile` at that exact coordinate. The player clicks it, and the character follows the blue navigation path around obstacles.

**2. Height & Backstab Advantages (Visual Rules):**
Instead of coding "if attacker.y > defender.y", we use Godot's visual dot-product or simple Y-axis checks in tiny "glue" scripts attached to the attack animations.
*   **High Ground:** If the attacker's Y-position is higher than the defender's, the AnimationPlayer plays a visual "Buff" particle effect (a glowing arrow pointing up) and plays a heavy "CRUSH" sound effect.
*   **Backstab:** Attach a small **Area3D** to the *back* of every enemy's 3D model. If your character's attack hitbox overlaps with this "Back Area3D", the game triggers a critical hit animation and a massive damage number pops up.

### Game 3: The *Trials of Mana* System (Real-Time Action)
This is fast, fluid, and relies on dodging and charging attacks. Because it's real-time, we need tight, responsive controls.

**1. The "Sword Trail" Hitbox:**
Just like in the turn-based game, we attach an **Area3D** to the character. But for real-time, we attach it specifically to the *weapon* sprite.
*   When the player presses "Attack", the `AnimationPlayer` plays the slash. 
*   For the 0.3 seconds the sword is swinging, the Area3D is turned on. If it touches an enemy, damage is dealt. This prevents "phantom hits" where you swing the air but the enemy takes damage.

**2. The Dodge Roll (I-Frames):**
In action RPGs, dodging gives you "Invincibility Frames" (I-Frames) so you can roll *through* enemy attacks.
*   Create a `Dodge_Roll` animation in the AnimationPlayer.
*   Add a track that targets the character's main **CollisionShape3D** (the physical body).
*   At frame 0.1, set the CollisionShape to `Disabled = true`. At frame 0.5, set it back to `Disabled = false`. 
*   *Result:* The player becomes physically intangible to enemy hitboxes while rolling. It feels incredibly responsive and requires zero complex state-machine coding.

**3. Charging Attacks:**
When the player holds the attack button, you want a visual charge-up (like the Sakuraba rock guitar swelling in the background).
*   In the AnimationPlayer, create a `Charge_Up` animation. 
*   Use a **Scale Track** to visually make the character or their weapon glow/grow slightly, and a **Particle Track** to spawn swirling energy. 
*   If they release the button, play the `Heavy_Smash` animation. If they get hit, the AnimationPlayer is interrupted, and the charge is lost.

extends Node

var is_online: bool = false

func _ready():

    var response: Dictionary = Steam.steamInit()

        is_online = false

func unlock_achievement(achievement_name: String):

# --- LEADERBOARDS ---

func upload_score(leaderboard_name: String, score: int):
    if is_online:
        # Find the leaderboard ID from Steamworks backend
        Steam.findLeaderboard(leaderboard_name)

# This listens for Steam to say "I found the leaderboard!"
func _on_leaderboard_find_result(leaderboard_handle: int, found: int):
    if found == 1:
        # Upload the score! (Score is an integer, like seconds or kill count)

3. **The 2.5D Trick:** To make the 2D sprites (trees, rocks, NPCs) blend perfectly with the 3D GridMap floors, ensure all your `Sprite3D` nodes have **"Shaded" enabled** in the Inspector. This forces the 2D images to catch the 3D shadows from your trees and buildings, grounding them in the diorama.

### Step 4: Performance & "Off-Screen" Management
2.5D games can be heavy because you are rendering 3D geometry *and* high-res 2D sprites simultaneously. Since you are targeting modern hardware, we don't need to make ugly compromises, but we do need to be smart about **Processing**.

1. **The AI Sleep Mode:** Your LimboAI Behavior Trees (from our Enemy AI step) are constantly calculating pathfinding and line-of-sight. If an enemy is two screens away, they shouldn't be thinking.
   * Add a **VisibleOnScreenNotifier3D** node to your Enemy prefab. 
   * Visually connect its `screen_entered` signal to turn *on* the AI script, and `screen_exited` to turn *off* the AI script. 
   * *Result:* The game only uses CPU power to calculate enemy tactics when the player is actually looking at them or fighting them.
2. **Audio Culling:** If a battle is happening off-screen, or an ambient waterfall is far away, use Godot's **AudioStreamPlayer3D** (which has built-in distance attenuation) instead of standard 2D audio players. This naturally fades out sounds based on physical distance, saving audio mixing overhead.

### Step 5: The Designer's Assembly Line (Your Daily Workflow)
To keep your sanity, follow this strict order of operations when building a new Hub or Dungeon:

1. **Greybox Phase:** Use basic grey 3D cubes and the GridMap to block out the physical space. Test the walking speed, the camera swoop angles, and the NavigationRegion3D paths. *Do not place a single tree or sprite yet.*
2. **Lighting Phase:** Add your `DirectionalLight3D` and `WorldEnvironment`. Set the mood (Dawn, Dusk, Cave). Lighting dictates the scale and feel of the 2.5D sprites.
3. **Population Phase:** Drag in your Lego Chunks. Place your `Sprite3D` trees, rocks, and NPCs.
4. **Logic Phase:** Place your Enemy spawners, Dialogic trigger zones (for NPCs), and Time Portal markers.

---

### 1. The VRAM Trap (Why 16K will hurt your players)
When you import an image into Godot, it doesn't just sit on the hard drive; it gets loaded directly into the GPU's Video RAM (VRAM) when the player opens the map. 
*   **A 4K Texture** takes up about **20-30 MB** of VRAM (when compressed by Godot).
*   **An 8K Texture** takes up about **80-120 MB** of VRAM.
*   **A 16K Texture** takes up **nearly 500 MB to 1 GB** of VRAM just for *one single image*.

If a player is on a Steam Deck, a Linux laptop, or an older PC, loading a 1GB map texture will cause the game to stutter violently, crash, or force the engine to dump other vital assets (like your 2.5D character sprites) out of memory to make room. 

### 2. Godot's Import Limits
By default, Godot 4 is optimized for standard hardware. 
*   If you drop a 16K image into Godot, the engine might automatically shrink it down to 8K or 4K during the import process to protect the game, meaning you did all that extra rendering work in Wonderdraft for nothing!
*   While you *can* go into Godot's Project Settings (`Rendering -> Limits -> Max Texture Size`) and force it to accept 16K, doing so immediately breaks your game's compatibility with lower-end hardware and consoles if you ever decide to port it later.

### 3. The Visual Reality (Do you even need 16K?)
Think about how the player interacts with the map. 
*   If the map is a **UI Overlay** (the player presses "M" and the map fills the screen), a 4K image is already larger than most players' monitors (which are usually 1080p or 1440p). A 4K map will look incredibly crisp and beautiful.
*   If the map is a **3D Plane** (the camera physically flies over the parchment like in *Golden Sun* or *Final Fantasy IX*), the camera is rarely zoomed in close enough to the "paper" to see the difference between 8K and 16K. 

---

### The "Pro" Alternative: Map Chunking (The AAA Trick)
If you are absolutely in love with the insane detail of a 16K map and you want the player to be able to zoom all the way in to read the tiny names of the villages, **do not use one giant image.** Use the industry-standard technique called **Map Tiling/Chunking**.

Instead of exporting one 16K image from Wonderdraft, you export the map as a grid of **sixteen 4K images**.
1.  **In Wonderdraft:** You design your massive world.
2.  **The Export:** You slice the map into a 4x4 grid (or use an external tool like Photoshop/GIMP to slice the exported image into 4K squares).
3.  **In Godot:** You lay these 4K images out on a 3D plane (or in a UI grid) like puzzle pieces. 

**Why this is genius for Godot:**
*   **Godot's `VisibleOnScreenNotifier2D/3D`:** You can attach this node to each 4K map chunk. If the player's camera is looking at the "Northern Continent," Godot only loads those specific 4K chunks into VRAM. The "Southern Continent" chunks stay unloaded, saving massive amounts of memory.
*   **UI Streaming:** If it's a UI menu, Godot handles loading multiple smaller textures much smoother than one colossal 1GB texture, preventing the "freeze" that happens when a player opens a massive map.

### Step 2: The Core Movement Script (Exploration)
We need her to move relative to the camera (so "Up" always means "Forward" into the screen, like *Octopath Traveler*). 

1. Attach a new script to the root `Player` (CharacterBody3D) node.
2. Paste this exact code:

```gdscript
extends CharacterBody3D

@export var speed: float = 5.0
@export var gravity: float = 9.8

@onready var anim_player = $AnimationPlayer

func _physics_process(delta):
    # 1. Apply Gravity so she stays on the 3D GridMap floor
    if not is_on_floor():
        velocity.y -= gravity * delta

    # 2. Get Keyboard/Controller Input (WASD or Left Stick)
    var input_dir = Input.get_vector("ui_left", "ui_right", "ui_up", "ui_down")
    
    # 3. Make movement relative to the Camera's angle
    var cam_basis = get_viewport().get_camera_3d().global_transform.basis
    var direction = (cam_basis * Vector3(input_dir.x, 0, input_dir.y)).normalized()
    direction.y = 0 # Lock movement to the horizontal plane

    # 4. Apply Movement and Animations
    if direction:
        velocity.x = direction.x * speed
        velocity.z = direction.z * speed
        
        if anim_player.current_animation != "Walk":
            anim_player.play("Walk")
    else:
        velocity.x = move_toward(velocity.x, 0, speed)
        velocity.z = move_toward(velocity.z, 0, speed)
        
        if anim_player.current_animation != "Idle":
            anim_player.play("Idle")

    move_and_slide()
```
*Note: Make sure you go to **Project -> Project Settings -> Input Map** and ensure "ui_left", "ui_right", etc., are mapped to WASD and your Controller's D-Pad/Stick!*
